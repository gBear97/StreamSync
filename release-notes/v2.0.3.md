StreamSync 2.0.3 fixes the Mac's stream swap, finds the stream in your only browser window on Windows, and fixes a few smaller things.

## What's new

- **Mac: the stream's browser comes forward when the film pauses.** "Show the stream while the film is paused" is on by default, but it never worked in the Mac app: macOS blocked it without asking. Now macOS asks whether StreamSync may control *System Events*, either the first time the film pauses or when you press **Refresh** beside **Stream app** in Settings, whichever comes first. Choose **Allow**. When the film plays again, the browser hides and the film comes back. If more than one browser is open, choose the stream's in **Settings > Stream app**. You can change the permission later in **System Settings > Privacy & Security > Automation > StreamSync**.
- **Windows: the stream is found in your only browser window.** With **Stream window** set to Automatic, StreamSync used to find the stream only when a window's title mentioned Twitch or Kick, so a VOD named after its video was missed. Now, if no title mentions them and exactly one browser window is open, it uses that window. The browsers it recognizes are Chrome, Edge, Firefox, Brave, Opera, Vivaldi, Chromium, Arc, LibreWolf, Waterfox, Floorp and Zen. With two or more browser windows open, even of the same browser, it still doesn't guess, and it asks you to pick one. If your stream plays somewhere other than a browser, choose its window in **Settings > Stream window**. Otherwise each pause will bring your one browser window forward in place of the film. To stop swapping altogether, untick "Show the stream while the film is paused".
- **VLC app: the window no longer freezes while VLC is slow.** With **Player** set to VLC app, the time display asked VLC for the time every 0.7 seconds, and the window froze whenever VLC was slow or stuck. It now uses what VLC last reported. If VLC hasn't answered for 2 seconds because it's closed or stuck, the time shows 0:00 until VLC answers again, instead of counting on. Pause, seek, mute and fullscreen still wait for VLC, so with a stuck VLC each of them can still hold the window for up to 2 seconds.
- **Mac: macOS 14 (Sonoma) or later.** The Mac app already needed macOS 14, and now it says so. On an older macOS, macOS won't open it and says it needs a newer version, where before the app started and then failed.
- **Mac updates: ready if macOS drops an old tool.** macOS 27 marks the way StreamSync opens an update's disk image as deprecated. From 2.0.3 on, if that way stops working, updates use its replacement instead. If both fail, the update now says plainly that the disk image couldn't be opened. This update itself is installed by the version you have now.
- **Watch party relay: a memory fix.** A connection could make the relay use more and more memory by sending film fingerprints under odd names. If you run a relay yourself, on your own computer or on a server, download `relay_server.py` again as the README's [Relay server](https://github.com/gBear97/StreamSync#relay-server) section shows, then stop the relay and start it again. The relay isn't part of the app, so updating the app doesn't update it. Apps of every version work with the new relay.

## Updating

- **From 2.0.x:** accept the update offer in the app, or use **Settings > Check now**. Your settings are kept.
- **From 1.x:** follow the "Upgrading from 1.x" steps in the [2.0.0 release notes](https://github.com/gBear97/StreamSync/releases/tag/v2.0.0). On Windows that means installing the setup program once by hand.
